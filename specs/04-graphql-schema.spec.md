# 04 — GraphQL Schema

## Purpose

Expose the domain via a code-first GraphQL schema (Pothos). Errors are first-class union members ("errors as data") — infrastructure bugs still surface through `errors[]` with masked messages.

## Location

- Schema: `packages/server/src/adapters/inbound/graphql/`
- SDL export: `packages/contracts/schema.graphql` (emitted at build time)
- Server integration: Apollo Server 5 mounted on Fastify via `@as-integrations/fastify`

## `@wa/contracts` package

- `packages/contracts/package.json` — name `@wa/contracts`, `type: module`, no runtime deps
- `packages/contracts/schema.graphql` — canonical SDL, checked into git, regenerated by `pnpm --filter @wa/server build:schema`
- `packages/contracts/codegen.ts` — GraphQL Code Generator config (reads `./schema.graphql`, writes to `packages/web/src/gql/`)
- Frontend `@wa/web` depends on `"@wa/contracts": "workspace:*"` for TypeScript type imports of the generated client
- CI runs `pnpm --filter @wa/server build:schema && git diff --exit-code packages/contracts/schema.graphql` to catch drift

## Complete SDL (target output)

```graphql
"""Kinds of activities we score."""
enum ActivityKind {
  SKIING
  SURFING
  OUTDOOR_SIGHTSEEING
  INDOOR_SIGHTSEEING
}

"""A resolved geographic location."""
type Location {
  id: ID!
  name: String!
  country: String!
  admin1: String
  latitude: Float!
  longitude: Float!
  timezone: String!
  population: Int
}

"""One contributing factor of a score, e.g. 'fresh snow' or 'low wind'."""
type ScoreComponent {
  label: String!
  """0..1 normalized contribution."""
  value: Float!
  """0..1 weight of this component in the overall score."""
  weight: Float!
}

"""A 0..100 desirability score plus its breakdown."""
type Score {
  value: Int!
  components: [ScoreComponent!]!
}

"""Score for a single day."""
type DailyScore {
  """ISO date (YYYY-MM-DD) in the city's local timezone."""
  date: String!
  score: Score!
}

"""7-day scoring for one activity in one city."""
type ActivityRanking {
  activity: ActivityKind!
  dailyScores: [DailyScore!]!
  bestDay: DailyScore!
  """0..100, mean of the top-3 daily scores."""
  overallScore: Int!
}

"""Success shape for the top-level query."""
type ActivityRankings {
  city: Location!
  """Sorted by overallScore descending."""
  rankings: [ActivityRanking!]!
  """Human-readable summary, either template or Claude-generated."""
  summary: String!
  """ISO 8601 timestamp."""
  generatedAt: String!
}

"""Common shape for all domain errors."""
interface DomainError {
  message: String!
  code: String!
}

type CityNotFoundError implements DomainError {
  message: String!
  code: String!
  query: String!
}

type AmbiguousLocationError implements DomainError {
  message: String!
  code: String!
  """Top 5 candidates sorted by population descending."""
  candidates: [Location!]!
}

type UpstreamUnavailableError implements DomainError {
  message: String!
  code: String!
  """e.g. 'open-meteo-forecast', 'open-meteo-geocoding'."""
  provider: String!
}

union ActivityRankingsResult =
    ActivityRankings
  | CityNotFoundError
  | AmbiguousLocationError
  | UpstreamUnavailableError

type Query {
  """
  Score all four activities for a city over the next 7 days.
  Either provide cityQuery (which will geocode + disambiguate) or locationId
  (obtained from a previous AmbiguousLocationError.candidates entry to skip geocoding).
  """
  activityRankings(cityQuery: String, locationId: ID): ActivityRankingsResult!

  """
  Search for locations by name. Used by the frontend command palette.
  """
  geocode(query: String!, limit: Int = 5): [Location!]!
}
```

Dates are `String` (ISO 8601) — no `graphql-scalars` DateTime. Frontend formats via `Intl.DateTimeFormat`.

## Pothos wiring

```ts
// adapters/inbound/graphql/context.ts
import type { Logger } from 'pino';
import type { RankActivitiesUseCase } from '../../../application/rank-activities.usecase.js';
import type { GeocodeUseCase } from '../../../application/geocode.usecase.js';
import type { Location } from '../../../domain/location.js';

export interface Context {
  readonly logger: Logger;
  readonly rankActivities: RankActivitiesUseCase;
  readonly geocode: GeocodeUseCase;
  readonly requestId: string;
}

// Backing source types Pothos maps to schema types.
// Domain returns tagged union; interface source is discriminated by 'kind'.
export type DomainErrorSource =
  | { kind: 'CityNotFound'; query: string }
  | { kind: 'AmbiguousLocation'; candidates: readonly Location[] }
  | { kind: 'UpstreamUnavailable'; provider: string };
```

```ts
// adapters/inbound/graphql/builder.ts
import SchemaBuilder from '@pothos/core';
import type { Context, DomainErrorSource } from './context.js';
import type { RankingResult } from '../../../domain/ranking-result.js';
import type { RankedForecast } from '../../../domain/ranked-forecast.js';
import type { Location } from '../../../domain/location.js';

type ActivityRankingsSource = Extract<RankingResult, { kind: 'Ok' }>;

export const builder = new SchemaBuilder<{
  Context: Context;
  Interfaces: { DomainError: DomainErrorSource };
  Objects: {
    ActivityRankings: ActivityRankingsSource;
    ActivityRanking: RankedForecast;
    Location: Location;
  };
  Scalars: { ID: { Input: string; Output: string } };
}>({
  plugins: [ /* no runtime plugins needed for MVP */ ],
});
```

Types are defined with `builder.objectType`, `builder.enumType`, `builder.interfaceType`, `builder.unionType`.

**`__resolveType` reads only the `kind` field** on the domain source. No fallback to constructor name — the domain returns tagged data, never class instances, for union members.

## Resolver contract

Resolvers are thin — **validate, delegate, map**:

```ts
// adapters/inbound/graphql/queries/activity-rankings.ts
builder.queryField('activityRankings', (t) =>
  t.field({
    type: ActivityRankingsResult,
    args: {
      cityQuery: t.arg.string(),
      locationId: t.arg.id(),
    },
    async resolve(_root, args, ctx) {
      const input = ActivityRankingsInputSchema.parse(args);   // Zod
      const result = await ctx.rankActivities.execute(input); // domain
      return toGraphQL(result);                                // mapper
    },
  }),
);
```

`ActivityRankingsInputSchema` (Zod):
- Requires exactly one of `cityQuery` (min 2 chars) or `locationId`.
- If both provided → `locationId` wins, log warning.
- If neither → throw `GraphQLError` with `BAD_USER_INPUT` code.

## Mappers (`adapters/inbound/graphql/mappers.ts`)

Domain `RankingResult` (tagged union) → GraphQL union payload. `Date` → ISO string. Snake-case? Never — domain already uses camelCase.

## Errors-as-data policy

- `RankingResult.kind === 'CityNotFound' | 'AmbiguousLocation' | 'UpstreamUnavailable'` → union member with `code: 'CITY_NOT_FOUND' | 'AMBIGUOUS_LOCATION' | 'UPSTREAM_UNAVAILABLE'`.
- Any thrown exception in a resolver → Apollo Server 5's default error formatter, wrapped by our `formatError` that:
  - Strips stack trace in prod
  - Adds `extensions.requestId` from `AsyncLocalStorage`
  - Preserves `BAD_USER_INPUT` code for Zod errors
  - Logs full error with pino at `error` level

## Fragment strategy (frontend)

The frontend uses graphql-codegen client-preset with fragment masking. Every component declares its own fragment; parents combine them.

Example fragments the frontend will define (documented here so schema is designed to support them):
```graphql
fragment DomainErrorFields on DomainError { message code }
fragment LocationFields on Location { id name country admin1 timezone latitude longitude }
fragment ActivityRankingsFields on ActivityRankings {
  city { ...LocationFields }
  summary
  generatedAt
  rankings { activity overallScore bestDay { date score { value } }
             dailyScores { date score { value components { label value weight } } } }
}
```

## Apollo Server 5 integration (Fastify)

`packages/server/src/adapters/inbound/graphql/apollo.ts`:

```ts
import fastifyApollo, { fastifyApolloDrainPlugin } from '@as-integrations/fastify';
import { ApolloServer } from '@apollo/server';
import {
  ApolloServerPluginLandingPageLocalDefault,
  ApolloServerPluginLandingPageProductionDefault,
} from '@apollo/server/plugin/landingPage/default';
import type { FastifyInstance, FastifyRequest } from 'fastify';
import { randomUUID } from 'node:crypto';
import { schema } from './builder.js';
import type { Container } from '../../../composition-root.js';
import type { Context } from './context.js';
import { getRequestId } from '../../../infrastructure/request-context.js';

const isProd = process.env.NODE_ENV === 'production';

export function buildApollo(fastify: FastifyInstance): ApolloServer<Context> {
  return new ApolloServer<Context>({
    schema,
    formatError: (formattedError, _error) => {
      // requestId comes from AsyncLocalStorage; stack masked in prod. See Errors-as-data policy.
      return { ...formattedError, extensions: { ...formattedError.extensions, requestId: getRequestId() } };
    },
    introspection: isProd ? process.env.EXPOSE_INTROSPECTION === 'true' : true,
    plugins: [
      fastifyApolloDrainPlugin(fastify),
      isProd
        ? ApolloServerPluginLandingPageProductionDefault({ footer: false })
        : ApolloServerPluginLandingPageLocalDefault({ embed: true }),
    ],
  });
}

export async function buildContext(
  request: FastifyRequest,
  container: Container,
): Promise<Context> {
  const requestId = (request.headers['x-request-id'] as string | undefined) ?? randomUUID();
  const logger = container.logger.child({ requestId });
  return {
    logger,
    rankActivities: container.rankActivities,
    geocode: container.geocode,
    requestId,
  };
}
```

Called by `main.ts` (see [Fastify server layout](#fastify-server-layout)) — `buildApollo(fastify)` returns the started server; `buildContext` is passed to `fastifyApollo(apollo)` at registration time.

**Prod-safety details** (all critical for a public Fly.io deployment):
- Landing page in prod is the redirect page, **never the interactive playground**.
- `introspection` is **OFF in prod by default**; codegen doesn't need it (reads `contracts/schema.graphql` file). Set `EXPOSE_INTROSPECTION=true` in prod only if intentionally allowing schema discovery.
- `fastifyApolloDrainPlugin` handles graceful shutdown (replaces the older `ApolloServerPluginDrainHttpServer`).

Pinned versions: `@apollo/server ^5.0.0`, `@as-integrations/fastify ^3.0.0`, `graphql ^16`.

### `infrastructure/request-context.ts` exports (referenced above)

```ts
import { AsyncLocalStorage } from 'node:async_hooks';
import fp from 'fastify-plugin';
import { randomUUID } from 'node:crypto';

export interface RequestContext {
  readonly requestId: string;
}

const als = new AsyncLocalStorage<RequestContext>();

export function runWithContext<T>(ctx: RequestContext, fn: () => T): T {
  return als.run(ctx, fn);
}

export function getRequestId(): string | undefined {
  return als.getStore()?.requestId;
}

// Fastify plugin: installs ALS + echoes x-request-id back on response
export const requestContextPlugin = fp((fastify, _opts, done) => {
  fastify.addHook('onRequest', (req, reply, next) => {
    const requestId = (req.headers['x-request-id'] as string | undefined) ?? randomUUID();
    reply.header('x-request-id', requestId);
    runWithContext({ requestId }, () => next());
  });
  done();
});
```

Add `"fastify-plugin": "^5"` to `packages/server` deps.

## Fastify server layout

`packages/server/src/main.ts` composes plugins in this exact order (order matters — later plugins can rely on earlier ones):

```ts
import Fastify from 'fastify';
import fastifyHelmet from '@fastify/helmet';
import fastifyCors from '@fastify/cors';
import fastifyRateLimit from '@fastify/rate-limit';
import fastifyStatic from '@fastify/static';
import fastifyApollo from '@as-integrations/fastify';
import path from 'node:path';
import { loadEnv } from './infrastructure/env.js';
import { createLogger } from './infrastructure/logger.js';
import { requestContextPlugin } from './infrastructure/request-context.js';
import { buildContainer } from './composition-root.js';
import { buildApollo, buildContext } from './adapters/inbound/graphql/apollo.js';

// 1. Preamble — env, logger, DI container, Apollo instance
const env = loadEnv();
const rootLogger = createLogger(env);
const container = buildContainer(env, { logger: rootLogger });

const fastify = Fastify({ loggerInstance: rootLogger });

// 2. Apollo must be constructed with a Fastify reference so the drain plugin can register handlers
const apollo = buildApollo(fastify);       // sets up ApolloServer + fastifyApolloDrainPlugin(fastify)
await apollo.start();

// 3. Global infra: security headers + CORS + request-id + rate limiter
await fastify.register(fastifyHelmet, { contentSecurityPolicy: false });   // CSP handled at frontend
await fastify.register(fastifyCors, { origin: env.CORS_ORIGIN.split(',') }); // dev-only origin allowlist
await fastify.register(requestContextPlugin);                                // AsyncLocalStorage + x-request-id echo
await fastify.register(fastifyRateLimit, {
  max: env.RATE_LIMIT_MAX,
  timeWindow: env.RATE_LIMIT_WINDOW_MS,
});

// 4. Health — registered BEFORE Apollo and static so it cannot be shadowed.
// Rate limit is disabled per-route so K8s / Fly.io probes never get 429'd.
fastify.get('/health', { config: { rateLimit: false } }, async () => ({ status: 'ok' })); // liveness

// 5. GraphQL
await fastify.register(fastifyApollo(apollo), { path: '/graphql', context: (req) => buildContext(req, container) });

// 6. Static + SPA fallback — MUST be registered LAST so it doesn't intercept /graphql or /health
if (env.NODE_ENV === 'production') {
  const webDistDir = new URL('../../web/dist', import.meta.url).pathname;
  await fastify.register(fastifyStatic, {
    root: path.resolve(webDistDir),
    prefix: '/',
    wildcard: false,      // let setNotFoundHandler do SPA fallback
  });
  fastify.setNotFoundHandler((req, reply) => {
    if (req.method !== 'GET') return reply.status(404).send({ error: 'Not found' });
    return reply.sendFile('index.html');   // SPA fallback: /city/lisbon → serves the React shell
  });
}

// 7. Listen + graceful shutdown
await fastify.listen({ port: env.PORT, host: '0.0.0.0' });

for (const sig of ['SIGINT', 'SIGTERM'] as const) {
  process.on(sig, async () => {
    await fastify.close();     // triggers apolloDrainPlugin, drains rate limiter, flushes logs
    process.exit(0);
  });
}
```

The snippet is self-contained: every symbol either comes from an import at the top or is declared in the preamble. An implementer can copy this file, install the dependencies listed in imports, and it runs.

Key points:
- **`/health` checks ONLY app liveness** — no upstream probing. Rationale in [spec 00 §Cross-cutting decisions](00-overview.spec.md#cross-cutting-decisions-invariants-across-all-modules). Prevents K8s cascading failure when Open-Meteo is down. A separate `/ready` is not defined: it would be static-identical to `/health` today; if a meaningful readiness signal appears (DB pool warmed, prewarm complete), introduce it with real logic rather than a placeholder.
- **Static-file handler is registered last** so it never shadows `/graphql` or `/health`.
- **`setNotFoundHandler`** implements SPA fallback: any unknown GET route returns `index.html` (React Router takes over client-side).
- **Rate limit applies globally** — an alternative is `@fastify/rate-limit` per-route config, e.g. bump limit on `/graphql` for typeahead-heavy operations. For MVP the global limit is enough; see [spec 05 §Rate limit handling on the frontend](05-frontend-architecture.spec.md) for how the client debounces to stay within it.

## Rate limiting

Per-IP token bucket via `@fastify/rate-limit`, applied globally (including `/graphql`). Config:
- 60 req per 60 s window per IP by default
- 429 response with `Retry-After` header
- Configurable via env: `RATE_LIMIT_MAX=60`, `RATE_LIMIT_WINDOW_MS=60000`
- `/health` excluded via per-route `config: { rateLimit: false }`

## SDL export

- Build script: `pnpm --filter @wa/server build:schema` runs a small Node script that constructs the Pothos schema and writes SDL to `packages/contracts/schema.graphql`.
- This file is checked into git — enables `graphql-codegen` on the frontend without a running server.
- CI verifies `schema.graphql` is up-to-date (`schema:check` script).

## Invariants

- `activityRankings` never returns `null` inside the union — always one of the four members.
- `ActivityRankings.rankings` always has 4 entries (one per activity), sorted by `overallScore` desc.
- `ActivityRankings.generatedAt` is set by `ClockPort.now()` (testable).
- All error unions include `code` — clients switch on `code`, not on `__typename` alone.
- Zod input validation happens **before** the resolver calls the use case.

## Rejected alternatives

| Rejected | Chose instead | Why |
|---|---|---|
| Errors via top-level `errors[]` | Union types | Client-side handling clearer; API self-documenting |
| `graphql-scalars` DateTime | ISO `String` | Fewer deps; frontend already needs `Intl.DateTimeFormat` |
| Global error code enum | Per-error `code: String!` | Extensible without schema breaking changes |
| Schema-first (SDL + resolvers) | Code-first (Pothos) | Single source of truth; drift-free; type inference |
| Nexus | Pothos | Better maintained, better types, official plugins |
| GraphQL Yoga | Apollo Server 5 | JD says GraphQL only; Apollo more universally recognised |
| Custom rate-limit middleware | `@fastify/rate-limit` | Battle-tested, well-tuned defaults, one line |
